File Inspector는 AutoJs6 파일 관리자에 있는 모든 파일을 검사합니다. 파일을 한 번만 읽어 CRC32, MD5, SHA-1, SHA-256 등 7가지 체크섬을 계산하고, 파일의 형식, 크기, 헤더를 표시합니다. 배포처가 공개한 체크섬을 붙여 넣으면 파일이 온전한지 확인할 수 있습니다. 검사는 읽기만 하며 원본 파일을 수정하지 않습니다.

### 시작하기

1. AutoJs6의 "플러그인 센터"에서 이 플러그인이 활성화되어 있는지 확인합니다.
2. AutoJs6 파일 관리자를 열고 검사할 파일을 찾습니다.
3. 파일 메뉴에서 "파일 검사"를 선택합니다 (AutoJs6 6.8.1 이상에서는 최상위 메뉴 "File Inspector" 아래에 있습니다).
4. 읽기가 끝나면 보고서에서 "파일 정보", "체크섬", "파일 헤더"를 확인합니다.

### 주요 기능

- **체크섬**: 한 번의 읽기로 CRC32, MD5, SHA-1, SHA-224, SHA-256, SHA-384, SHA-512를 함께 계산합니다. MD5와 SHA-1에는 "레거시"가 표시되며 보안 증명으로 쓰기에는 적합하지 않습니다.
- **무결성 검사**: 공개된 체크섬을 "예상 체크섬"에 붙여 넣고 "검증"을 탭하면 일치는 초록색, 불일치는 빨간색으로 표시됩니다. `sha256sum` 출력 줄 전체도 받습니다.
- **파일 정보**: 감지된 형식, 확장자, MIME 유형을 표시하고 내용이 텍스트인지 바이너리인지 추정합니다. ZIP 파일은 APK, JAR, Office 문서인지도 알려 줍니다.
- **파일 헤더**: 파일 앞부분 64바이트를 16진수와 ASCII로 나란히 표시하고, UTF-8, UTF-16, UTF-32 바이트 순서 표시 (BOM)를 감지합니다.
- **크기 대조**: 선언된 크기와 실제 크기를 함께 표시합니다. 읽는 동안 파일이 바뀌면 오류가 표시되므로 다운로드가 덜 된 파일이나 아직 쓰는 중인 파일을 알아챌 수 있습니다.
- **복사와 공유**: 체크섬과 파일 헤더를 각각 복사할 수 있습니다. "보고서 형식"에서 Markdown 또는 JSON을 고른 뒤 "보고서 복사"나 "공유"로 전체 보고서를 보냅니다. 파일은 만들지 않습니다.
- **읽기 진행 상황**: 큰 파일을 읽을 때 진행률, 속도, 남은 시간을 표시하며 언제든 "취소"할 수 있습니다. 실패하면 "다시 시도"를 탭합니다.

### 요구 사항

- Android 7.0 이상.
- AutoJs6 6.8.0 이상.
- 저장소와 네트워크 권한이 필요하지 않습니다. 플러그인은 파일 관리자에서 선택한 파일만 읽습니다.

### 자주 묻는 질문

**체크섬이 일치하지 않을 때의 대처**

먼저 붙여 넣은 체크섬이 이 파일의 배포 페이지에서 가져온 것인지 확인합니다. 그래도 일치하지 않으면 파일이 배포처의 원본과 다르며, 다운로드가 덜 되었거나 변경되었을 수 있습니다. 공식 배포처에서 다시 다운로드한 뒤 다시 검사하세요.

**체크섬이 일치한다는 의미**

일치는 체크섬이 공개된 원래 파일과 내용이 같다는 것만 보여 줍니다. 파일을 믿을 수 있는지는 체크섬을 어디서 얻었는지에 달려 있습니다. 공식 배포처가 HTTPS로 공개한 SHA-256 또는 SHA-512를 우선 사용하세요.

**줄 전체를 붙여 넣을 때 파일 이름 경고가 나타나는 이유**

`sha256sum` 같은 도구의 출력 줄 전체를 붙여 넣으면 플러그인이 줄에 있는 파일 이름을 대조합니다. 현재 파일 이름과 다르면 경고를 표시하여 이 파일의 체크섬이 맞는지 확인하도록 알려 줍니다.

**일부 파일을 검사할 수 없는 이유**

흔한 원인은 파일이 8 TiB를 넘는 경우, 읽는 동안 다른 앱이 파일을 바꾼 경우, 파일 관리자가 준 읽기 권한이 만료된 경우입니다. 오류 메시지에 원인이 표시되며, "다시 시도"를 탭하면 다시 검사합니다.
