# File Inspector

## О проекте

Инспектор файлов (File Inspector) — плагин-компаньон файлового менеджера AutoJs6. Выберите «Проверить файл» для любого файла — плагин прочитает его ровно один раз и одновременно вычислит контрольные суммы CRC32, MD5, SHA-1, SHA-224, SHA-256, SHA-384 и SHA-512, а также покажет на одном экране настоящую сигнатуру формата, размер и первые байты файла. Всё работает только на чтение: плагин не запрашивает разрешений на хранилище и сеть и никогда не изменяет исходный файл.

На странице отчёта есть поле «Проверка целостности»: вставьте контрольную сумму, опубликованную издателем файла, — плагин сам определит алгоритм и даст однозначный вывод «совпадает / не совпадает», так что сверять длинные шестнадцатеричные строки на глаз больше не нужно. Каждую сумму и снимок заголовка можно скопировать отдельно; перед копированием всего отчёта или системной отправкой выберите Markdown либо JSON.

## Возможности

- Одно чтение — все результаты: файл читается последовательно ровно один раз, и все семь контрольных сумм считаются одновременно; большие файлы не ждут нескольких проходов.
- Вставил — проверил: поддерживаются hex и отпечатки, Base64, SRI и полные строки `md5sum` / `sha256sum`; алгоритм определяется автоматически, а отличающееся имя файла вызывает предупреждение.
- Настоящий формат: распознаёт 26 распространённых сигнатур в ограниченной начальной выборке и по фиксированным смещениям, поясняет назначение ZIP-контейнеров APK/JAR/Office и оценивает текстовый либо двоичный характер по доле печатных символов и энтропии.
- Заголовок как на ладони: первые 64 байт файла показываются в сопоставлении «hex + ASCII», плюс определяются метки порядка байтов (BOM) UTF-8 / UTF-16 / UTF-32.
- Двойная сверка размера: отображаются и заявленный файловым менеджером, и фактически прочитанный размер; если файл изменился во время чтения, проверка сразу завершается ошибкой — так выявляются недокачанные и ещё записываемые файлы.
- Управляемый прогресс: для больших файлов видны прочитанные байты, скорость и оценка оставшегося времени; чтение можно отменить в любой момент, а неудачную проверку — повторить одним касанием.
- Результаты сразу в дело: отдельно копируйте любую сумму или снимок заголовка, а весь экранный результат экспортируйте как Markdown либо JSON в буфер обмена или системную панель, не создавая файл.
- Устаревшие алгоритмы помечены: MD5 и SHA-1 несут значок Legacy — напоминание, что они больше не годятся как доказательство безопасности.

## Как пользоваться

1. Скачайте APK и одноимённый файл проверки `.apk.sha256` из одного официального Release, установите APK и включите его в центре плагинов AutoJs6 (требуется AutoJs6 с кодом версии 5268 или новее).
2. Перед обновлением проверьте скачанный APK уже установленным Инспектором файлов; при первой установке сохраните APK и проверьте его после включения плагина. Вставьте 64-значный SHA-256 из файла проверки и убедитесь в зелёном совпадении; оба файла должны быть получены с одной доверенной HTTPS-страницы Release.
3. Откройте файловый менеджер AutoJs6 и найдите файл, который хотите проверить; подойдёт любой обычный файл.
4. Выберите в меню файла «Проверить файл» — чтение начнётся сразу, с живым прогрессом; по завершении появятся контрольные суммы, сигнатура формата и байты заголовка.
5. Чтобы проверить целостность, вставьте опубликованную контрольную сумму в поле «Проверка целостности» и нажмите «Проверить»: зелёный — совпадает, красный — не совпадает.
6. Кнопка рядом с суммой или под снимком заголовка копирует отдельное значение; выберите Markdown либо JSON для копирования или отправки всего отчёта, затем вернитесь в файловый менеджер.

> Поле принимает чистый hex, префиксы вроде `sha256: <значение>` или `MD5=<значение>`, отпечатки `AB:CD:EF`, CRC32 с `0x`, стандартный Base64, SRI вида `sha256-<base64>` и полные строки coreutils `<hex>  <файл>` или `<hex> *<файл>`. Регистр и пробелы по краям игнорируются; алгоритм выводится при уникальной длине, а отличающееся имя файла вызывает предупреждение.

## Разрешения и безопасность

Плагин не запрашивает разрешений на хранилище и сеть и может добраться только до одного файла, выбранного пользователем, — через временный content-URI только для чтения, выданный хостом; по окончании проверки доступ истекает, другие файлы недостижимы. Запросы из файлового менеджера проверяются по каждому полю — идентификатор действия, версия протокола, форма content-URI, имя файла, MIME-тип, заявленный размер, права только на чтение — а любой запрос с правами на запись или постоянными правами отклоняется сразу. Файл обрабатывается потоком только для чтения; в памяти остаются лишь ограниченные буферы, первые 4096 байт для анализа, первые 64 для показа и четырёхбайтовое окно сигнатуры PE, исходный файл не изменяется.

Чтобы каждая проверка оставалась предсказуемой, плагин соблюдает следующие пределы:

- Один файл — не более 8 TiB; за одно действие обрабатывается ровно один файл.
- Для анализа берутся не более первых 4096 байт и четырёхбайтовое окно сигнатуры PE, а показываемый заголовок остаётся длиной 64 байт; ввод ограничен 512 символами, а не-ASCII разрешены только в имени файла coreutils.
- Если фактически прочитанный размер отличается от заявленного, файл считается изменённым, и проверка завершается ошибкой с пояснением.
- Сравнение контрольных сумм выполняется за постоянное время для значений равной длины; MD5 и SHA-1 годятся лишь для сверки старых данных и не должны считаться стойкими к коллизиям.
